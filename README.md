# MyTime · 单文件个人时间中枢

一个**零依赖、零构建**的单文件 HTML 个人中枢：日历（月 / 周 / 日 / 年 / 议程）、习惯打卡热力图、看板、速记，支持多设备云端同步与桌面通知。

> 整个应用就是一个 `MyTime.html`，双击即可在浏览器打开；想多设备同步，把它托管到任意静态服务（如 Netlify）并接入自己的 Supabase 即可。

---

## 特性

- **单文件**：HTML + CSS + JS 全部内联，无需 npm、无需打包、无框架。
- **五大模块**：日历、习惯、看板、速记、提醒。
- **多设备同步**：基于 Supabase（Postgres），云端为唯一真相。
- **桌面通知**：事件到点弹出系统通知（需 https / localhost 环境并授权）。
- **数据自有**：JSON 导入 / 导出，本地优先，云端只在你授权时写入。

## 部署（3 步，约 20 分钟）

### 1. 创建 Supabase（免费）

1. 注册并登录 https://supabase.com ，新建一个 Project。
2. 进入 **SQL Editor**，执行：

   ```sql
   create table if not exists mytime_data (
     id   bigint primary key,
     payload jsonb
   );
   -- 关闭行级安全，使网页可用 anon key 直接读写（本项目靠 anon key 工作，必须关 RLS）
   alter table mytime_data disable row level security;
   ```

   > 也可在 **Table Editor** 手动建表：`mytime_data`，字段 `id`（类型 int8，设为主键）、`payload`（类型 jsonb），并关闭 RLS。

### 2. 取你的密钥

进入 **Project Settings → API**，复制：

- **Project URL**（形如 `https://xxxx.supabase.co`）
- **anon public key**（以 `eyJ` 开头的一长串 JWT）

> ⚠️ 永远不要把 `service_role` key 写进网页（那是管理员密钥，泄露即裸奔）。anon key 设计上可公开。

### 3. 部署 HTML

1. 打开 https://app.netlify.com/drop ，把 `MyTime.html` 拖进去，得到一个 `https://xxxx.netlify.app` 网址。
2. 用浏览器打开该网址 → **首次会自动弹出「配置云端同步」** → 粘贴你的 Project URL + anon key → 点「保存并启用」。
3. 之后该浏览器自动记住配置；其他设备 / 浏览器各自打开同一网址、各自配置一次，即可共享同一份数据。

**日常更新**：登录 Netlify → 进入该 Site 的 **Deploys** → 上传覆盖 `MyTime.html`（覆盖部署会**保住同一网址**，桌面通知授权不会失效）。

## 桌面通知（可选，但推荐）

任务到点时，会在**电脑右下角弹出系统通知**（即使网页在后台 / 最小化也能收到）。启用方式：

1. 打开页面后，若顶部出现蓝色横条「开启桌面通知」→ 点它 → 浏览器弹出授权框 → 点「允许」。
2. 授权成功后会立刻弹一条「桌面通知已开启」的系统提示，验证通道正常。

**如果点了按钮没反应 / 一直不弹授权框**：说明该网址已被浏览器记成了「禁止通知」，点按钮不会重新弹框。处理方式（任选其一）：
- 点地址栏左侧 🔒 锁图标 → 找到「通知」→ 改为「允许」，刷新页面；
- 或进浏览器设置（如 Edge/Chrome：`设置 → 隐私、搜索和服务 → 网站权限 → 通知`）→ 把本网址加入「允许发送通知」列表，刷新即可。

> 通知权限**按网址绑定**：换新网址（重新 Drop 部署）或换设备后，需在对应浏览器重新授权一次；若用「覆盖部署」保住同一网址，则一次授权永久有效。

## 隐私说明（重要）

- **本仓库不含任何个人凭据或数据**。`MyTime.html` 中的 Supabase 配置默认留空，由你本人在首次使用时填写，仅存于你浏览器的 localStorage。
- 每个使用者接入**自己独立的 Supabase 项目**，数据天然隔离、互不可见——你既看不到别人的，别人也看不到你的。
- 你的真实数据（日程 / 习惯 / 看板）只存在你自己的 Supabase 云端与本地缓存，**从不进入本仓库**。

---

## 同步原理（简述）

- 云端 `mytime_data` 仅一行 `id = 1`，作为该用户的共享状态。
- 打开页面先拉云端覆盖本地缓存；**只有本会话真正做过编辑**，才会把改动推上云（1.5 秒防抖 + 每 5 秒轮询补拉 / 补推）。
- 启动阶段云端尚未就绪前，**绝不推送**，避免把空数据覆盖掉真实数据（这也是早期踩过的坑，已修复）。
